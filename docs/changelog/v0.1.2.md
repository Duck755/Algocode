# v0.1.2

发布日期：2026-09-21

## 新增

- 引入多候选搜索：默认最多创建 3 个候选，在方向失败或收益不足时继续探索不同算法方案。
- 引入同候选细化：对已有统计显著正向前景、但尚未满足接受条件的候选重新打开，最多细化 2 轮。
- Analyze 新增问题结构、复杂度基线和算法候选分析，并要求至少 3 个可评估方案。
- Plan 新增 `algorithm`、`complexityBefore`、`complexityAfter`、`whyFaster` 和 `structureRef`。
- Benchmark 支持 stdin 多规模输入，以及短程序固定轮数的 benchmark harness。
- Compare 支持按 input 与 repeat 配对，使用配对置换检验、bootstrap 置信区间和 MAD 鲁棒波动。
- Decide 增加置信区间门控；增长指数下降可豁免固定百分比提升阈值。
- 阶段运行时只向模型暴露当前阶段允许的工具，并在每轮注入剩余轮次和剩余工具调用数。
- 连续修改候选后会强制运行候选自检，降低“只改不验”的风险。
- 新增候选重新打开和阶段回退事件，CLI 会显示回退原因、候选和轮次。
- `read_file` 遇到目录或不存在路径时会给出目录清单和下一步建议，而不是只返回 `file not found`。

## 修复

- 修复原始标准差波动被单个系统调度尖峰放大，导致高收益候选被错误判为无效或产生误导 warning 的问题。
- 原始 `variation_percent` 继续保留为诊断字段，样本有效性改为优先使用鲁棒波动。
- 修复 Benchmark 置信区间未参与接受决策的问题。
- 修复 `init` 与 `optimize` 的证据链在部分终端宽度和 CJK 字体下对齐错误的问题。
- 修复阶段进度完成后轨道仍残留、回退原因不输出的问题。
- 修复 Benchmark harness 重复调用同一固定输入、可能被全局缓存替代真实工作量的问题。
