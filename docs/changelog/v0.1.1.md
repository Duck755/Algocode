# v0.1.1

## 新增

- 新增 VS Code 扩展入口，支持在 `.py`、`.cpp`、`.cc`、`.cxx` 文件上右键优化。
- 新增 `algocode vscode install`，可安装内置 VS Code 扩展。
- `algocode status` 增加阶段进度展示：当前阶段、轮次、工具数量、active tool、last tool 和阶段耗时。
- `algocode report` 同时生成项目根目录 `report.md`，并保持内部 JSON/Markdown 产物不变。
- Analysis 入口命令支持字符串或数组形式，便于不同项目配置。
- `algocode init` 重做运行体验：TTY 下显示实时阶段轨道与耗时，结束时输出证据链（契约/基线/校验/基准/任务）和下一步菜单；非 TTY、`--json`、`--quiet` 自动关闭进度，`--progress/--no-progress` 可强制覆盖。
- `algocode init` 新增 `--yes`，用于跳过运行前确认。
- `algocode optimize` 与 `algocode retry` 重做运行体验：TTY 下用一行原地刷新的进度日志叙事，动作和阶段结束时定格为带 `✔`/`✖` 的永久日志行，阶段名与工具名全部中文。
- `algocode optimize` 结束时输出 `optimize · <status> · 耗时 <duration>` 摘要行、证据链（任务/耗时/阶段/候选/正确性/基准/提升/决策）和下一步菜单。
- `algocode optimize` 新增 `--progress/--no-progress`，`algocode retry` 同步支持。
- 进度日志只写入 `stderr`，复用事件日志与 `algocode status` 的同一套进度事实；非 TTY 只输出定格行且不写控制字符，`--json`/`--quiet` 完全关闭进度。

## 修复

- 修复 Contract 文件过滤时，候选 Worktree 路径本身包含 `.algocode` 导致的误过滤问题。
- 调整 Windows 下 Sandbox 后端选择，允许 WSL2 优先于 Native。
- 修复 `algocode optimize` 更新 `.algocode/current-task.json` 时向上层目录继承状态的问题：现在只合并本项目自身的状态，并写入完整的 `taskId`、`projectId`、`objective`、`language`、`gitRevision`、`dataDir` 与 `databasePath`（后两者为绝对路径），父目录残留的任务标识不再污染当前项目。

## 文档

- 文档站点新增 `快速上手`、`命令手册`、`用户指南`、`核心概念`、`参考文档` 和 `开发维护`。
- 新增简略工作流与完整工作流拆分说明。
