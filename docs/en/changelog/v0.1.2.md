# v0.1.2

Release date: 2026-09-21

## Added

- Multi-candidate search with up to three candidates by default, allowing exploration of different algorithmic directions when a direction fails or produces insufficient gain.
- Same-candidate refinement: a candidate with significant positive evidence but no acceptance yet can be reopened for up to two refinement rounds.
- Analyze now includes problem structure, complexity baseline, and algorithm-candidate analysis, requiring at least three evaluable approaches.
- Plan now includes `algorithm`, `complexityBefore`, `complexityAfter`, `whyFaster`, and `structureRef`.
- Benchmarks support stdin input matrices and a fixed-repeat benchmark harness for short-running programs.
- Compare supports pairing by input and repeat, paired permutation tests, bootstrap confidence intervals, and MAD-based robust variation.
- Decide adds confidence-interval gates; a clear growth exponent reduction can bypass the fixed percentage threshold.
- Phase runtime exposes only allowed tools for the current phase and injects remaining turns and tool-call budgets.
- Repeated candidate edits force a candidate self-check, reducing the risk of changing code without verifying it.
- New candidate reopen and phase fallback events expose the reason, candidate, and iteration.
- `read_file` now reports directory contents and next-step hints when a path is a directory or missing.

## Fixed

- Fixed misleading warnings and false invalidations caused by raw standard deviation being inflated by a single scheduling spike.
- Raw `variation_percent` remains diagnostic; validity now prioritizes robust variation.
- Fixed Benchmark confidence intervals not participating in acceptance decisions.
- Fixed evidence-chain alignment under some terminal widths and CJK fonts.
- Fixed stale phase tracks and missing fallback reasons after phase progress completed.
- Fixed the benchmark harness repeatedly calling one fixed input that could be dominated by a global cache rather than real work.
